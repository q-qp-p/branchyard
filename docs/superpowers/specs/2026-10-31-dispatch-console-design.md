# Dispatch: the console as a dispatcher's desk

Written 31 October 2026, with a second pass on the console's look on 1 November 2026. The web console ([companion](../../companion.md)) stops being an inbox and becomes three surfaces for three jobs, and the engine and server gain the two abstractions those surfaces need. This page says what the console is for, why the inbox was the wrong machine, what the person's experience demands of the backend, and what was built.

## What the console is for

Branchyard runs many agents at once, each on its own branch, and asks one person to supervise them. Agent time is cheap; the person's attention is the one scarce resource in the system. The console's job is therefore to spend that attention only on decisions no agent can make, with exactly the evidence each decision needs, and otherwise to show that the yard is healthy without being opened.

## Why the inbox was wrong

The desktop console ([design](2026-10-29-desktop-console-design.md)) grouped branches into lanes and opened each in a conversation pane, like a mail client. An inbox's unit is a message, and every row has the same shape. The console's unit is a decision, and decisions have different shapes:

| Decision | Who waits | Clock | Evidence it needs | Answer |
|---|---|---|---|---|
| Approval | the agent, parked mid-turn | none: the turn waits at the approval until someone answers | the call and its arguments, which policy asked, what the branch was doing | allow, deny |
| Question or escalation | the agent, parked | none | the question, what it was doing | a sentence; approve, deny |
| Merge | delivery; no agent | none, but main drifts | what it says, what it ran, the files, the diff, who else holds those files | merge (held), follow up |
| Stop | nobody | none | the failure, the last thing it did, cost so far | resume, follow up |
| Stall | nobody | none | how long it has been silent | look, cancel |

An inbox sorts these by arrival, puts a parked agent under a merge review, forces open-read-find-act-return on every one, has no time axis, no liveness and no lineage, and makes the sidebar fight the detail for the same width. Its action button sits top right, as far from the diff as the page allows.

## How the experience shapes the abstractions

Each surface asked the backend for one thing it could not say.

**A branch must say it is parked.** The engine recorded an approval ask in the effects store and waited for it inside the turn; the branch's status stayed `running`, and only a separate approvals list knew. Every surface that shows a branch (the lanes, the board, `by ls`, the stall detector) had to join that list itself, or lie. So `BranchInfo` gains `awaiting`: what the running turn is parked on, with the ask's id, what it asks and since when. It is read from the pending asks when a record is listed or looked up, never stored, so it is exact the moment the ask is answered, and it is `None` whenever the branch is not running. This was a field and not a new `BranchStatus` variant on purpose: `running` is the lifecycle state (a harness process is alive, a cancel still applies, the lease holds), and "parked" is a property of that turn, like `stalled`. A parked turn is never stalled; it moves only when someone answers.

**A decision must be a resource.** The deck wants the decisions in the order to take them, and the order is a rule the client should not have to know: a parked agent first, the one that has waited longest before the rest, because it moves only when answered; then the branches ready to merge, because delivery waits on them; then the stopped and stalled, which nothing waits on. Nothing expires. So the server gains `GET /v1/repos/{repo}/decisions` (`DecisionList`): each decision carries its kind, its branch, who waits (`agent`, `delivery`, `nobody`), since when where the server knows, the branch's status and candidate, and the ask or the question itself. The console had been assembling questions from every delegating branch's inbox on its own; that moved into the server with the rest.

**The turn is a record the client can read.** The report view needs each tool call beside the paragraph it produced, and a receipt per turn. The event page already carries both in order, so the client's conversation reducer attaches the calls that precede a paragraph to that paragraph and keeps each turn's start and end. No server change. The one figure the page could not derive is a turn's own cost, since a harness may report its session's running total: the engine records it when the turn's metering has settled (`turn_cost`, what the branch's cost grew by in that turn, none when nothing measured it; [budgets](../../delegation.md#budgets)), so the receipt shows time, cost, calls and the diff, and the strip keeps the branch's total.

Two things stayed deliberately client-side or were left for later: hold-to-merge and the undo window are mechanisms of the page (an allow or a deny is held for eight seconds before it is sent, and the agent stays parked meanwhile; a merge is a 700 ms hold, because the server offers no undo for it), and the ground plan (which files are in two hands) came in a follow-up: `GET …/ground` reads every open branch's diff when asked and lists each changed path with the open branches that changed it, the branch page's inspector gains a Ground tab beside Changes, and a merge card names the files another open branch also holds.

## The surfaces

**Decide** (`#/attention`, which `#/inbox` and `#/approvals` still open): one card at a time, shaped for its decision, the question at the top, the evidence in the middle, the answers at the bottom. Keys: Enter takes the first action (held, for a merge), `n` denies, `s` sends the card to the back, `o` opens the branch, `f` opens it with the message box focused. The bay beside the card shows the answers held for undo, then what is next, parked agents first. A merge card shows what the agent said last, what its calls did (the harness reports what ran, not whether it passed), the changed files with their counts, and the first lines of the first file's diff.

**Watch** (`#/`, home): every open branch on one clock, the last hour to scale, now at the right edge. A running branch's bar is hatched; a wait on the person fills amber from the moment the turn parked; a ready branch draws a thin green line until it is merged; merged branches fold to ticks. Each row has its cost and one action: Answer, Merge, Steer, Resume or Open. Steer opens a one-line box under the row, so a sentence reaches a running turn without opening the branch.

**Work** (`#/b/…`): the turn as a report. The agent's text is a column with a margin; each tool call is a note in the margin beside the paragraph it preceded, named after the tool, and opens the Activity tab. Each turn ends with a receipt: how it ended, how long it took, how many calls read, edited and ran, and the commit with its counts. On a phone the margin becomes a line above the paragraph. The "N tool calls" fold is gone.

The sidebar stays. It is the navigation, its lanes already read `awaiting`, and removing it was not what made the inbox wrong. The strip keeps its confirmed Merge; the deck's merge is the held one.

## Knowledge work

A knowledge workspace has no branch to merge, but a person still waits on it, so it has decisions too. A decision for a workspace is one of two things. An `output` is a file a session published from its current turn that nobody has accepted: delivery waits on the person, so it sorts with the ready branches. A `session` is one that failed, was interrupted or never started, which nothing waits on, so it sorts with the stopped branches; a session whose plan waits for approval parks its agent and comes first. They are the `Decision` the repository's list already returns, with the workspace, the session and the output named in optional fields, and they come from `GET /v1/projects/{project}/decisions` because the sidebar, the picker and the workspace list all choose a project, not a workspace, and one request then covers every workspace in it. The rules are the ones the workspace page already applies, moved to the server so a client does not copy them: an output counts when `finalize` would accept it, and a failed session stops counting once a newer session exists in its workspace, because Try again starts a new session and leaves the failed one behind.

The evidence on a card is the deliverable. A diff is the proof that a branch changed what it said it would; for a document, the proof is the document, so the output card mounts the same preview component the Outputs tab does, a table or a page image, under the question "Analyst delivered backlog.csv", with Download original beside it and a held Accept as the first answer. Where the server cannot make a preview the component says so and offers the original, and the card still accepts. A session card shows what happened and the last thing the session said, and resumes an interrupted session or opens the workspace to try again. The deck merges the repository's cards with the listed project's; the board of a project draws its running sessions, its stopped ones and its delivered outputs on the same clock as branches.

## Second pass: the surface system

The first cut had the right model and a flat look: one shadow, one border colour, the sidebar, the page and the panels the same white, the board a table of rows clustered at "now" with the lower two thirds of the page empty, the deck one card above two empty folds. The second pass keeps every surface's job, every key and every selector the tests pin, and changes what the surfaces are made of and what they show.

**Elevations.** Three, each a background, a border and a shadow, light and dark designed together, every neutral tinted (no pure white or black): the *page* (`--surface-page`, the sunk ground the report and the board sit on), *raised* (`--surface-raised`: tiles, the board, the strip, the inspector, the bay's cards, the receipt, the diff), and *overlay* (`--surface-overlay`: the deck's card, the composer, menus, dialogs). The sidebar is chrome, `--surface-side`, a step darker than the page, so the eye starts on the work. A raised thing that can be pressed lifts on hover: one step of shadow, one pixel up, under `prefers-reduced-motion: no-preference` only. Radius runs 6, 8, 12, 16; spacing sits on four pixels; numbers that line up use tabular figures.

**Watch.** The board uses the page: five tiles say the yard in numbers (in flight, need you, ready, merged today, spent), and the rows draw what happened, not just that something did. Each row's track is read from the branch's own events: a turn is a bar from its prompt to the status that ended it, each tool call a tick where it started, a wait on the person amber from the moment the turn parked, an answered wait paler, a merge a green tick. The clock's window fits the work: the smallest of a fixed list (4 minutes to a day, quarters on round numbers) that holds the oldest branch shown, so a yard that started minutes ago is not lost in an hour. Under the board, the day's decisions and where the money went.

**Decide.** The card is the one object with weight: the overlay elevation, a header band tinted by its kind with how long it has waited, the evidence as labelled sections side by side (an approval shows what the agent was doing beside what it asks: the tool, the call's first arguments, which policy asks, when it parked), and the answers as a firm footer. The next card peeks under it; the bay stacks the rest. Below, instead of two empty folds, what was decided today, read from the answered approvals (`GET …/approvals?all=true`), the merged branches and the effect ledger; the folds moved under **More**.

**Work.** The report has a measured column (68 characters) with the prompt as its headline and the turn's number and time in the margin; the margin notes are 12-pixel text joined to their paragraph by a hairline; the receipt is a block of labelled figures; the strip is a raised bar with the state and the actions grouped; the composer an overlay over a fade of the page; the diff's file header stays in view while it scrolls; every inspector tab carries its count.

**Empty states.** A yard with no branches, a deck with nothing to decide, a branch with no turns and a workspace with no sessions each say what the place is for and what to do, with the action.

The demo behind the README screenshots now runs its branches on Claude Code's stream-json profile, played by a script, so each turn reports what it spent and the cost column is filled; the branches start seconds apart and space their calls, so the board shows the shape of real work in the three minutes the demo runs. It never fakes a timestamp.

## Evidence

Hermetic. `crates/branchyard/tests/effects.rs` shows a branch parked on a tool approval listed and looked up with `awaiting` naming the ask, and none once answered. `crates/branchyard-server/tests/effects.rs` shows the server's decisions putting the parked branch first, waiting on the agent, with the ask attached, and the decision gone once answered. `tests/companion_browser.rs` runs a server whose person policy asks before a write: the board draws the parked branch with its amber wait, the lane says "waiting for you", the tab title counts it, the deck shows the ask first, Later sends it to the back and it comes round, Enter holds an allow that Undo takes back with nothing sent, Enter again sends it after the window, the branch finishes and comes back as a merge card with its changed file. The same run shows a tool call as a margin note that opens Activity. It also has a delegating parent run a child that asks it a question and waits (the real `by mcp` behind the fake agent): the tab title counts the question as it arrives, after a reload the deck's first card names the child and the question, Enter in the answer box sends the text with nothing held, the card leaves, the title stops counting it, and the API shows the answer in reply to the question in the child's inbox and in the text its turn ended with. For knowledge work, `crates/branchyard-server/src/console/tests/decisions.rs` shows a published CSV listed as an `output` until it is accepted, a failed session listed after it until another session starts, and an interrupted one until it is resumed; `tests/console_workspace_browser.rs` shows the output cards on Needs you with the server's preview (a table with the preview converter, the "cannot make previews" state without it), Accept held to settle one, and the project board's delivered rows. The README screenshots were regenerated on 31 October 2026 with `tools/readme_screenshots/generate.py` (hermetic, Chrome 153.0.8010.12 through Playwright 1.63.0, the table preview rendered by the converter under Bubblewrap 0.9.0); they show the board and the deck with an approval parked in front, the branch page with its margin notes and receipt, and the workspace.
